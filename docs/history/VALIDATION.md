- 容器测试：10 项桌面测试全部通过，实际捕获红色测试窗口、验证键盘修饰键和文本、指针坐标与按钮、会话退出和遗留按键释放。

## 本地 H.264 / WSS 验证（2026-10-21）
该次检查在无板卡环境中进行。使用此前保存的屏幕截图叠加移动标记，软件编码为 1280×720 H.264；不是实时 HDMI 采集。

- 浏览器控制台分别验证 WebCodecs 与 MSE 出帧，保留录制栏和输入状态。
- 本地独立 Nginx 实例终止 TLS；探针显式信任临时证书，验证 HTTPS 登录、Secure Cookie、WSS Upgrade 和两种封装的实际解码。
- 5 秒 WSS 探针：Annex-B 解码约 60fps，负载约 2.24Mbps；fMP4 解码约 59fps，负载约 2.26Mbps。
- 10 秒测试加入 10Mbps 消费限速与 80ms ACK 延迟：解码约 60fps，负载约 2.40Mbps，最后 ACK 往返约 85ms。ACK 指标包含客户端处理/人工延迟，不能当作操作到画面的延迟。
- 无 ACK 客户端验证有界发送与超时断开；原始 JSON 与浏览器截图位于被 Git 忽略的 `artifacts/wss/`。

新编码参数尚未在 ROCK MPP 上运行，实际 WAN、显示器到浏览器的延迟、目标机键鼠反馈和不同浏览器仍待实机验收。2026-10-20 的 SSH/JPEG 诊断证据保存在 `artifacts/video-diagnosis/`，描述的是当时的旧播放策略。

## 视觉定位检查（2026-10-20）
该次检查连接板子时，`kvm-web` active、USB configured，但 HDMI 查询返回 `No locks available`，共享帧不存在。因此先用已保存的真实 HDMI 图调试。后续复查时 HDMI 恢复，已通过 SSH 读取当场真实画面：1920×1080 的浏览器网页，读取时共享帧年龄约 26ms。人工接管标记仍在，未执行板端点击。

| 已保存的真实画面 | 当前候选数 | 区域数 | 默认返回页数 |
| --- | ---: | ---: | ---: |
| Zed 编辑器 | 58 | 7 | 3 |
| macOS 键盘设置 | 118 | 13 | 5 |
| macOS 显示设置 | 140 | 13 | 5 |

当场采集的网页有大幅建筑插画，检测出 266 个候选、23 个细分区域（全部输出需要 8 页）。逐张观察后加入高密度总览：现在首个 MCP 返回只有一张九区域总览；选择右下角 C09 后，返回总览与两张局部图，共 24 个候选，每张分别 14/10 个。弹窗关闭按钮在局部图中为 T234，原图点击中心 `(1808.5, 818.5)`；它与旁边插画的线条候选可以清楚区分。

逐张查看标记图后进行了三项调整：

- 编辑器菜单的 Go/Run 在单纯边缘检测时漏检，局部对比度补充后出现对应标记。
- 孤立鼠标光标导致工具栏分图过高，按大间隙拆分后成为单独区域。
- 设置页的重复图标框和文字碎片较多；合并后键盘设置页从 144 个候选降至 118 个，显示设置页从 152 个降至 140 个。候选减少不等于点击成功率提升。

通过浏览器打开实际导出的检查页，点击 T055 后页面显示原图点击点 `(1570, 398.5)`，对应键盘设置中的“编辑…”区域。浏览器截图接口在当时返回 `Unable to capture screenshot`，因此报告的可视证据采用导出的标记 PNG；网页事件通过浏览器实际交互验证。

自动测试还通过真实 stdio MCP 验证了多张 ImageContent、分页、网格和按 ID 点击调用；这些调用的输入目标是测试记录后端。真实 HDMI → 新工具 → USB → 目标界面反馈的闭环仍需在交还人工控制后验收。

本地证据位于被 Git 忽略的 `artifacts/vision/zed-v2/`、`settings-v2/`、`display-v2/`。当场原图与采集元数据是 `live-now.jpg` / `live-now.capture.json`，最新完整检查页在 `live-refined/`，C09 工具返回图在 `live-focus/`。PNG、原图、`manifest.json` 和检查页均保留，方便继续比较。
